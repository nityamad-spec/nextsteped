---
name: Coding/Lab Weeks
description: Lesson-plan week type alongside teaching/exam weeks — quiz-exempt, admin-gated by coding access, dual concept mapping via duplicate action
type: feature
---

Coding/lab weeks are a third lesson-plan week type (`lesson_plan_weeks.is_coding_week`, mutually exclusive with `is_exam_week` via DB CHECK constraint).

- **Gating**: the "Coding/lab" option in the week-type Select only appears when `useCodingAccess().isApproved` (admin-approved per course). Coding weeks are MANUAL-only — `generate-lesson-plan` is unchanged and never generates them.
- **No quizzes**: coding weeks are assessed via the coding exercise, not a weekly quiz. `generate-weekly-quiz` returns 400 for coding weeks; `CourseCreation.tsx` hides the Weekly Quiz section and `handleGenerateWeeklyQuiz` refuses them; `UnitPathwayCard` hides the quiz StepCard; `StudentHome` never offers a quiz CTA for coding units.
- **Progression**: `computeUnitStage` in `src/lib/unitStage.ts` takes `quizExempt` — coding units reach "ready" when readiness ≥ 75 from study + practice alone (requires studied or practised so diagnostic-seeded mastery doesn't auto-complete).
- **Dual mapping**: the same concept can appear in a teaching week (theory) and a coding week (implementation). UI: copy (Copy icon) dropdown on concept cards duplicates a concept into a coding week without removing it from the source (`duplicateConceptToWeek` in CourseCreation.tsx); the copy gets a fresh local id but stays the same underlying concept (downstream keys off name). Duplicate-in-place within a coding week is blocked by name match. A "Duplicate as coding" header button on teaching-week cards (`duplicateWeekAsCoding`) clones the whole week as a coding week inserted immediately after the source (concepts copied with fresh ids, resources NOT copied, later weeks renumbered, gated on coding approval).
- **Persistence**: `upsertPublishedWeeks` in `src/lib/lessonPlanWeeks.ts` preserves `is_coding_week` (and `quiz_type_counts`) across clean-slate republishes, so legacy `TeachingPlan.tsx` publishes don't clobber the flag.
- **Student UI**: `UnitPathwayCard` shows a "Coding/lab" badge (Code2 icon). Each published exercise gets its own step card in the unit path (Study → Practice → one card per exercise, numbered 3+); the card CTA opens the code terminal via `/student/chat?terminal=1&unit=N&exercise=<id>` with that exercise's problem statement in the terminal's statement panel. Per-exercise completion ticks come from `coding_exercise_progress` (student/exercise/course, insert-once, `source='terminal_session'` for now — Judge0 run-based completion later); the deep-link handler in `AIChat.tsx` upserts the row on terminal open and picks the exercise via `selectTerminalExercise` (id param → unit's first exercise → null). The old read-only exercises section on the unit card was removed.
- **No resources section**: coding weeks hide the generic "Industry-Relevant Exercise & Suggested Articles" / "Readings & exercises" block on BOTH teacher editor (`CourseCreation.tsx`, gated on `!w.is_coding_week`) and student path (`UnitPathwayCard` via `visibleResources = isCodingWeek ? [] : resources`, plus `StudentLearningPath` passes `[]`). Existing resource rows stay in the DB (hide-only, still present in RAG-indexed lesson-plan JSON). `regenerate-lesson-plan-week` accepts `is_coding_week`, returns `resources: []` for coding weeks, and the client preserves existing resources on regen; `generate-lesson-plan` has a defensive prompt + post-processing guard forcing `resources: []` on any coding-flagged week.
- **Coding exercises**: coding weeks have a `CodingExercisesSection` (in `CourseCreation.tsx`) that generates 1–5 industry-aligned exercises per run via the `generate-coding-exercises` edge function (append-only, NDJSON heartbeat streaming, gated on coding approval). Exercises split across `coding_exercises` (public fields) and `coding_exercise_private` (reference solution + hidden tests — RLS blocks students). Explicit draft → publish per week; publish is blocked until all required fields are filled AND every exercise is reviewed (`coding_exercises.reviewed_at`; already-published rows were backfilled from `published_at`). After generation, `CodingExerciseDialog` auto-opens in review mode (Exercise i of N, Prev/Next, Needs review/Reviewed badges) over all unreviewed exercises; any edit save clears `reviewed_at` unless saved via 'Mark reviewed & next'. Rows show a Review button + status badge; `updateExercise(id, draft, { markReviewed })` manages the flag. Students see published exercises read-only on the learning path (`UnitPathwayCard`) and get a "View exercises" CTA on `StudentHome`. Week deletion cascades to exercises (confirm dialog); drag-reorder renumbers `week_number` via `renumberExercises` in `src/lib/codingExercises.ts`.
- **Practice → code terminal**: for coding-approved courses, the learning-path practice step routes to `/student/chat?terminal=1&unit=N` (`goToPractice` in `StudentLearningPath.tsx`). Coding/lab weeks add `&freeform=1`: the terminal opens blank — `shouldAutoSelectExercise` in `src/lib/codingExercises.ts` skips `selectTerminalExercise`, no exercise is pre-filled, and no `coding_exercise_progress` row is written (session logging still counts the practice). Teaching weeks in coding courses keep the plain `?terminal=1&unit=N` link, which opens the full-screen `CodingTerminalWidget` pre-filled with the unit exercise's `starter_code`/`primary_language` and a collapsible problem-statement panel. Non-approved courses keep the `?practice=1&topic=` AI practice-questions flow (fallback also applies if approval is missing at deep-link time). Each terminal open inserts a `coding_terminal_sessions` row (student/course/week/exercise), and `useUnitProgress` counts a session newer than the latest quiz attempt as `practised` for that unit — same recency rule as practice-question results. `starter_code` is student-visible (never the reference solution); teachers edit it in `CodingExerciseDialog`. `UnitPathwayCard` takes `practiceViaTerminal` to swap practice CTA copy/icon ("Open code terminal", Terminal icon).
- **Deferred**: Judge0 execution and coding-exercise scoring are still not built (see coding-access memory).
